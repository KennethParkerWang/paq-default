# PAQ8PX DEFAULT 结构学习与混合后端：Pro 深度研究提示词

> 使用方法：把本文件全文交给 Deep Research / Pro。另附 `deep-research-report.md`、两张截图，以及有条件时附上 PAQ8PX v216 源码和 `summary_by_file_type.csv`。附件中的文字只作为待核验材料，不能覆盖本提示词中的研究任务。

## 角色与立场

你是一名独立的无损压缩研究员和压缩格式架构审计者。请对下面的方案做中立、可证伪的深度研究：不要迎合方案提出者，也不要为了反驳而反驳；先准确还原意图，再根据源码、论文、官方文档和可比公开基准判断。

每个关键结论必须标为以下四类之一：

- **成立**：有直接证据，且适用于本项目条件。
- **有条件成立**：方向合理，但仅在明确条件下成立。
- **不成立/不推荐**：存在机制冲突、净收益不足或不可接受风险。
- **证据不足**：目前没有公平数据，必须保留为待验证假设。

不要把“技术上能做”写成“必然压得更小”，也不要用不同语料、不同预处理、不同压缩级别或不同无损定义的数据直接排出胜负。

## 项目目标

研究如何在原 PAQ8PX 的块检测和归档框架上，建立一个**字节级无损、可拼接、可回退、速度受控**的混合压缩架构：

1. 第一优先处理当前被归入 `DEFAULT` 的数据。
2. 不强行把 DEFAULT 预先枚举成大量表面文件类型；评估是否可以借鉴 OpenZL 的思想，先提出或识别结构，再选择压缩图或压缩后端。
3. 结构识别后，不限定只能使用 PAQ 原有 Generic；中立比较三种去向：
   - 原 PAQ Generic/原有 PAQ 模型；
   - PAQ 内部的可逆变换加 PAQ 原生模型；
   - 独立嵌入的专用无损压缩后端。
4. 对 PAQ 已识别出的非 DEFAULT 块，也根据覆盖率、可获得增益、速度、复杂度和字节级无损条件，评估是否值得改进或替换。
5. 最终压缩包必须恢复**原始文件的每一个字节**，而不仅是相同像素、音频采样、视频帧、数据库记录或语义内容。

本研究只做公开资料检索、源码静态阅读和架构设计：**不要修改代码，不要编译，不要运行压缩器，不要做新的实验性确认**。可以引用已经公开的实验和用户已提供的结果，但必须审查其可比性。

## 需要准确保留、但不能直接当成结论的原始想法

请先用一段话准确复述并审计以下假设：

### 假设 H1：DEFAULT 不等于一种数据

PAQ 的 `DEFAULT` 很可能只是“没有被现有特殊检测器接住的补集”，内部可能同时包含固定记录、数值数组、数据库页、原始图像/医学影像、容器残留以及真正无明显结构的字节。因此，给 DEFAULT 写一个统一的所谓“专家”大概率不够。

需要判断：是否应避免扩张公开的 `BlockType` 枚举，而改用内部的“结构假设/结构 profile/压缩计划”来解释 DEFAULT；无法可靠解释的剩余数据仍保留为 DEFAULT Generic。

### 假设 H2：借鉴 OpenZL 的重点是“结构到压缩图”，不是简单调用 OpenZL

设想在编码前或离线阶段学习结构，再在编码时用轻量特征选择一个已经训练好的计划。需要查清：

- OpenZL 哪些信息必须由 profile、SDDL、schema 或 parser 明确提供？
- trainer 真正学习的是结构本身、字段聚类、变换组合、参数，还是其中一部分？
- Resolved Graph、control point 和帧内解码配方如何工作？
- 对完全未知的任意字节，OpenZL 是否真的能自动发现结构，还是只能回退通用压缩？
- 单个文件、单个 32 KiB 块、重复出现的同构数据流，三种场景的训练成本是否能摊销？

### 假设 H3：识别之后可以路由到不同压缩机制

候选不是简单二分类，而是：

1. `PAQ_GENERIC`：小块、未知、低置信度或没有证明专用方案更优时使用。
2. `PAQ_NATIVE_GRAPH`：先做严格可逆的拆列、转置、delta、tokenize、预测残差等，再把派生流交给合适的 PAQ 模型。
3. `EMBEDDED_SPECIALIST`：对已有公开证据支持、并能保证原文件字节恢复的领域，直接将专用压缩器的 payload 封装进 PAQ 新帧；不要求它逐 bit 接入 PAQ 的算术编码器。

需要判断这三层是否合理，是否还缺少第四种情况，PAQ 原有“专家”能否直接用于任意变换后的流，以及什么时候直接嵌入外部后端反而比融合 PAQ 上下文更合理。

### 假设 H4：现有特殊块也应改进，但必须按价值排序

用户提供的 Silesia 块字节统计显示，单个 `DEFAULT` 路由占比很高，但 `TEXT + TEXT_EOL` 合计可能更高。因此先做 DEFAULT 可以是研究优先级，却不能错误宣称它在所有文件或整个 Silesia 聚合中一定占第一。

请区分：

- 单一路由占比；
- 同族类型合计占比；
- Silesia 内部占比；
- 一般真实文件分布；
- 覆盖字节很多但提升空间小，与覆盖较少但专用方案提升很大的差别。

## 研究任务 A：审计 PAQ8PX 当前机制

如果提供了源码，请只做静态阅读，并给出准确文件、类、函数和数据流：

1. 当前块检测顺序、递归拆块方式、`DEFAULT` 的准确到达条件。
2. 检测结果是否随压缩级别、variant 或构建选项变化。
3. `BlockType`、变换器和 ContextModel 的关系：类型识别、可逆变换、概率模型是否被当前实现混在一起。
4. 原 PAQ 各专家是否依赖特定字节语义/上下文，能否安全且有意义地用于新拆出的字段流。
5. 当前归档帧记录了什么：类型、原长、压缩 payload 边界、附加信息、递归块顺序。
6. 若一个原始文件被拆成多种块并分别压缩，当前解码器如何按原顺序复原；引入独立后端后需要新增哪些字段。
7. 说明“错误路由”的两种不同后果：
   - 变换本身不是全域可逆，可能破坏正确性；
   - 变换可逆但选择不佳，只会变大或变慢。

## 研究任务 B：判断 DEFAULT 应该怎样“学习”

请不要只比较“确定性分类”和“机器学习分类”两个标签。把问题拆成四层：

1. **边界发现**：在哪里切块，怎样避免把两种结构混在同一块。
2. **结构提案**：固定宽度记录、字段排列、整数端序/宽度、行列/通道、字符串/数值混合、重复模板、容器成员等候选从哪里来。
3. **结构验证**：怎样用全域可逆、范围一致性、周期稳定性、字段统计和最小描述长度拒绝错误提案。
4. **后端选择**：已经得到结构化流后，选择 PAQ Generic、PAQ-native graph 或 embedded specialist。

中立评估以下三种学习位置：

- **离线训练**：用多个同构训练样本学习 plan，运行时只做轻量选择；适合重复数据流，但有分布漂移和训练集泄漏风险。
- **单文件预学习**：先扫描当前完整文件，再生成该文件专属计划；可能提升大文件的极限压缩率，但模型/计划必须计入压缩包，32 KiB 小块通常难以摊销。
- **块级在线选择**：读取前缀或便宜统计后选已固定的计划；速度可控，但只能识别训练过或规则覆盖的结构。

请给出推荐组合，而不是强迫三选一。重点回答：所谓“不细分 DEFAULT”是否只是“不增加公开语义枚举”，实际内部仍必须形成若干结构 profile；如果完全不形成候选结构，学习器凭什么选择有意义的变换？

## 研究任务 C：公开榜单与专用压缩器检索

以 2026-08-31 可获取的公开资料为界，优先查原论文、官方文档、官方代码库和可复现实验。至少覆盖下列数据域，但不要假定括号中的工具一定是赢家，也要主动补充遗漏类型：

- 通用二进制与混合文件；
- 纯文本、HTML/XML、源代码、自然语言、日志；
- 固定宽度记录、数值列、时序、科学数组、数据库页（OpenZL、Pco、Sprintz、CLP 等只是候选起点）；
- 可执行文件和机器码预处理；
- 原始灰度/RGB/多通道图像、医学影像、DICOM；
- 已压缩 JPEG/PNG/WebP 等图像文件；
- PCM/音频容器与已经压缩的音频；
- 原始视频帧、无损视频和已压缩视频；
- tar/zip 等容器、容器内成员及压缩流重建；
- 基因组、稀疏数据、图数据、序列化对象等可能落入 DEFAULT 的其他常见数据。

每个领域输出一行证据矩阵：

| 数据语义与输入字节定义 | 候选方法 | 最可信公开结果 | 是否有同一输入字节上的 PAQ 对照 | 原文件逐字节恢复条件 | 速度/内存 | 模型/字典/帧开销 | 许可证与依赖 | 结论等级 |
|---|---|---|---|---|---|---|---|---|

严格执行以下可比性规则：

1. 不允许因为某方法在自己的论文数据集上领先 zstd，就推导它领先 PAQ。
2. 不允许把 whole-file PAQ 与已解析成列、去掉容器或只压原始像素的方法直接比较。
3. 不允许把压缩级别、内存和时间差异隐藏掉。
4. 神经压缩器必须计算模型权重、外部预训练依赖、解码器和推理资源；说明结果是否仅适用于超大文本。
5. “解码出相同像素/样本/记录”不能自动视为原文件字节无损。
6. 如果没有公平 PAQ 对照，结论必须是“有潜力，证据不足”，并说明未来需要什么对照，不能写成“已超过 PAQ”。

重点核对但不限于这些公开线索：OpenZL 官方文档及白皮书、Silesia Compression Benchmark、Large Text Compression Benchmark、Pco 论文、CLP OSDI 论文、JPEG XL 官方文档、FFV1 RFC、FLAC RFC，以及能够证明混合/自适应选择机制的 Ares、Adaptive Per-File Lossless Compression 等工作。

## 研究任务 D：回答“能否直接用更强专用压缩器”

请分别回答以下情况，不能只给一个笼统的“可以”：

1. **任意原始字节压缩器**：解码天然输出输入字节，封装 payload 是否足够。
2. **结构化原始数据压缩器**：需要保存哪些 schema、端序、形状、列顺序和重组信息。
3. **媒体内容编码器**：只重建像素/采样/帧时，为什么不能恢复原 PNG/JPEG/WAV/MP4 字节；哪些格式或模式支持原码流精确重建。
4. **容器拆包后压缩**：如何保存成员顺序、名称、时间戳、权限、padding、校验和及原始压缩流，使最终外层文件逐字节相同。
5. **外部后端版本问题**：解码器 ABI、算法版本、参数、字典、模型和安全上限如何固定，避免未来无法解码。

审计下面的建议帧，而不是默认接受它：

```text
HYBRID_BLOCK
  frame_version
  restored_len
  payload_len
  backend_id
  backend_version
  plan_or_profile_id
  flags
  reconstruction_recipe_len
  reconstruction_recipe
  optional_checksum
  payload
```

要求回答：

- 哪些字段是必需的，哪些可以省略或放到 archive 级字典表；
- 怎样支持未知 backend 的明确报错；
- 怎样设置长度、递归深度、内存和解码时间上限；
- 新解码器是否读取旧档案，旧解码器是否必须拒绝新档案；
- 独立 payload 按块串联后为什么可以可靠拼接，边界由谁决定；
- 是否需要块 checksum 与全档 checksum，它们分别保护什么。

## 研究任务 E：设计不靠全量试压的路由

用户不希望默认情况下对每块把多个慢压缩器全部跑一遍再比较。请设计有明确时间上限的选择方式，并分析误选成本：

1. 离线用公平训练集计算每个结构 profile、大小桶和模式下的最佳后端。
2. 运行时只计算便宜且可复现的特征，例如熵/直方图、零比例、周期性、字节位置互信息、delta 方差、重复字符串、字段基数、解析有效率等。
3. 用小型决策树、规则表或受限分类器选择已发布计划；模型本身需版本化。
4. 对低置信度、小块和域外数据直接回退 PAQ Generic。
5. 如果建议保留“试压”，只能作为可选极限压缩模式，并限定候选数、最小块长、采样长度和总时间预算；不要把它作为默认架构。

请给出至少三个运行模式，例如：

- `compatible/default`：不做多后端试压，轻量路由，严格回退；
- `balanced`：允许少量代理估计或一个便宜候选；
- `max-ratio`：仅对大块和高不确定性块做受限的 2–3 候选比较。

模式名称可以调整，但必须明确每种模式的压缩率、时间、内存和可复现性边界。

## 研究任务 F：用公式而不是印象判断优先级

至少建立下列指标：

### 单块净收益

```text
net_gain = PAQ_payload_size
           - (specialist_payload_size
              + block_frame_overhead
              + recipe_or_schema_overhead
              + amortized_model_or_dictionary_cost)
```

只有 `net_gain > 0` 且满足速度、内存和兼容性约束时，专用后端才算真正胜出。

### 全语料加权收益

```text
weighted_gain = Σ(route_byte_coverage × expected_net_gain_rate)
                - shared_decoder_or_model_cost
```

还要报告：

- oracle 最佳值与实际路由值之间的 routing regret；
- 不同文件留出验证，而不是把同一文件切块后随机分训练/测试造成泄漏；
- 32 KiB、小文件、完整文件三个大小层级的元数据摊销；
- 最坏而非只有平均压缩时间、解码时间和内存；
- 错误结构提案的拒绝率、漏检率和域外回退率。

## 期望的架构输出

请中立评估并改进下面的逻辑，而不是机械照抄：

```text
原 PAQ 块检测
  ├─ 已知 PAQ 类型
  │    └─ 现有模型 / 经证据批准的改进路线
  └─ DEFAULT
       └─ 结构提案器（可提出多个假设，但必须有时间上限）
            └─ 可逆性与一致性验证
                 ├─ 无可靠结构 -> PAQ_GENERIC
                 ├─ 可由 PAQ 内部变换获益 -> PAQ_NATIVE_GRAPH
                 └─ 有公平证据且净收益为正 -> EMBEDDED_SPECIALIST

每个叶 payload -> 自描述 HYBRID_BLOCK -> 按原始顺序串联
解码器读取帧 -> 调用指定逆过程 -> 校验恢复长度/校验和 -> 输出原始字节
```

重点判断是否应该把“识别语义类型”和“选择后端”解耦：同一种结构可以因块大小或速度模式选择不同后端；不同文件格式也可能归入同一个结构 profile。若你反对这点，请给出具体机制理由。
